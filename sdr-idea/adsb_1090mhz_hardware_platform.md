# 如何自己做一个硬件平台，单独实现 1090MHz ADS-B 信号的接收和解码

这份文档只回答一个问题：

**如果不直接依赖现成 SDR 软件平台，而是自己做一个专用硬件平台，如何完成 1090MHz ADS-B 信号的接收、检测、解码与输出？**

先说结论：

- **如果目标是“器件最少 + 最容易开发”**，最推荐的平台不是自研超外差，也不是“分立 LNA + Mixer + ADC + FPGA”全链路，而是：  
  **1090MHz 天线 + 1090MHz SAW/LNA 前端 + 集成零中频/低 IF 接收芯片或成熟 SDR 接收芯片模块 + MCU/SoC**
- **第一版最务实方案**：尽量把“射频接收、频率变换、I/Q 或包络输出”收敛到 1 颗接收芯片或 1 块成熟前端模块中，数字侧优先用 MCU/MPU 完成检测和解码
- **只有在追求更高性能、抗强干扰、更远接收距离时**，再升级为：  
  **1090MHz 天线 + LNA + SAW/BPF + 下变频/零中频 + ADC + FPGA/高速 MCU**
- **最快做出原型的路线**：先用成熟接收芯片或接收前端模块，把重点放在数字基带和协议解码链路
- **真正难点不在协议本身**，而在：
  - 射频前端灵敏度与动态范围
  - 1090MHz 带外干扰抑制
  - 前导码同步检测
  - 1Mbps PPM 脉冲判决
  - CRC 校验与误包过滤
- **建议的工程顺序**：先做“能稳定收包”，再做“更远距离、更低误检、更完整解析”

---

# 一、先明确目标：你要做的到底是什么

1090MHz ADS-B 接收平台，本质上是一个**1090MHz 专用数字接收机**。  
它要完成下面几件事：

1. 接收 1090MHz 附近的 ADS-B / Mode S 信号
2. 从噪声和干扰中检测出合法脉冲
3. 完成前导码识别
4. 进行 PPM 比特判决
5. 解出 56bit 或 112bit 报文
6. 完成 CRC 校验
7. 解析 ICAO 地址、高度、位置、速度、呼号等字段
8. 通过 UART / USB / Ethernet / Wi-Fi 输出给上位机或显示终端

所以它不是“通用 SDR”，而更像一个：

- **1090MHz 专用接收机**
- **ADS-B / Mode S 解码终端**
- **航空目标数据接收模块**

---

# 二、ADS-B 1090ES 的基础信号特性

## 1. 工作频率
ADS-B 1090ES 工作在：

- **1090 MHz**

## 2. 调制方式
1090ES 使用：

- **PPM（Pulse Position Modulation，脉冲位置调制）**
- 速率约 **1 Mbps**
- 每个 bit 周期约 **1 us**
- 每个脉冲宽度约 **0.5 us**

可以简单理解为：

- 一个比特时间是 1us
- 脉冲出现在前半个 bit 或后半个 bit，用来表示不同 bit 值

## 3. 报文长度
常见长度有：

- **56 bit**：短报文
- **112 bit**：长报文，ADS-B 最常见

## 4. 前导码
每个 Mode S / ADS-B 报文前都有固定前导码：

- 前导码长度约 **8 us**

接收机通常先做前导码检测，再进入比特判决。

---

# 三、从系统角度看，整个平台由哪些部分组成

一个完整自研 ADS-B 平台，通常分成 6 层：

## 1. 天线层
负责把 1090MHz 空口信号接进来。

## 2. 射频前端
负责：

- 低噪声放大
- 带通滤波
- 带外干扰抑制
- 增益分配
- 限幅或 AGC（可选）

## 3. 频率变换 / 模拟基带
把 1090MHz 信号变成适合 ADC 的 IF 或零中频信号。

## 4. 数据采样层
ADC 把模拟波形数字化。

## 5. 数字基带处理层
负责：

- 能量检测
- 前导码匹配
- 比特判决
- 报文拼接
- CRC 校验
- 缓存输出

## 6. 输出与系统管理层
负责：

- 协议字段解析
- 上位机接口
- 网络发送
- 参数配置
- 统计与日志

---

# 四、最推荐的 3 种硬件实现路线

## 路线 A：超外差 / 低 IF + ADC + FPGA + MCU
**推荐度：高**  
**工程难度：高**  
**性能潜力：高**

### 架构
`1090MHz RF -> LNA/BPF -> Mixer -> IF -> ADC -> FPGA -> MCU`

### 优点
- 射频链路可控
- 动态范围和抗干扰能力更好
- 适合做高性能专用接收机

### 缺点
- 射频设计复杂
- 需要本振、混频器、IF 滤波器
- PCB 和调试工作量较大

### 适合场景
- 想真正做成专用接收机产品
- 后续希望扩展到高性能版本

---

## 路线 B：零中频 / 直接变频 + I/Q 采样
**推荐度：很高**  
**工程难度：中到高**  
**落地速度：较快**

### 架构
`1090MHz RF -> LNA/BPF -> 直接变频/IQ 接收 -> ADC -> FPGA/MCU`

### 优点
- 省掉复杂 IF 链路
- 易于与数字处理结合
- I/Q 数据更灵活，便于能量和时序分析

### 缺点
- 需要处理 DC offset
- 需要处理 I/Q 失衡
- 需要控制 LO 泄漏

### 适合场景
- 追求研发效率
- 想在复杂度和性能之间平衡

---

## 路线 C：集成接收芯片 + 数字解码板
**推荐度：最高（原型阶段）**  
**工程难度：中**  
**落地速度：最快**

### 架构
`1090MHz RF -> 外部 LNA + SAW -> 集成接收前端 -> 数字输出 -> FPGA/MCU`

### 优点
- 开发周期最短
- 射频难度最低
- 容易先证明“收得到、解得出”

### 缺点
- 芯片选型受限
- 参数不一定针对 1090MHz 最优
- 最终 BOM 和性能未必最好

### 建议
如果是第一版，最建议：

> **先用集成前端做通整个接收解码链路，再逐步专用化射频前端。**

---

# 五、如果从“最少器件、最容易开发”出发，优先选哪种平台

这一节只站在两个角度看：

1. **器件数量尽量少**
2. **研发门槛尽量低，能最快做出稳定原型**

如果按这个标准排序，推荐顺序其实很明确。

## 推荐顺序（按“自己做硬件平台”的第一版原型优先级）

> 这里特别说明：  
> **如果 RTL-SDR + PC 这类方案你已经实现过，那么它更适合作为“算法与接收效果基线”，而不再适合作为“自己做硬件平台”的主推荐方案。**  
> 也就是说，下面排序会把“可落到自己板级硬件”的方案放在更高优先级。

### 方案 P1：成熟 SDR 接收芯片模块 + 主控板（参考基线方案）
**推荐度：中**  
**器件数量：最少**  
**开发难度：最低**  
**是否适合第一版：适合做对照验证，不适合作为最终硬件方向首选**

### 典型结构
`1090MHz 天线 -> 1090MHz SAW/LNA（可外置） -> SDR 接收芯片模块 -> USB/UART/SPI -> 主控板`

### 适合原因
- 射频收发、频率合成、采样、接口很多已经在模块内做好
- 你不用第一版就处理 1090MHz 射频 PCB、阻抗控制、LO 泄漏、ADC 时钟这些硬问题
- 可以把主要精力放在：
  - ADS-B 前导码检测
  - PPM 判决
  - CRC
  - 报文字段解析
  - 数据输出

### 适合的实现方式
- **最省事**：直接采用成熟 USB SDR 模块，先在 PC 端验证
- **再进一步**：采用带并口/高速串口输出的射频接收模块，外接 MCU/SoC 做实时处理

### 缺点
- 平台不够“纯自研”
- 模块体积、成本、供电方式可能不如最终产品优雅
- 某些模块采样链路偏通用，不一定是 ADS-B 的最优性价比

### 第一版是否推荐
**如果你还没有任何可运行平台，它非常推荐；如果 RTL-SDR + PC 已经跑通，则它应降级为参考基线方案。**

---

### 方案 P2：1090MHz 前端模块 + 模拟包络/限带 + 高性能 MCU
**推荐度：高**  
**器件数量：少**  
**开发难度：低到中**  
**是否适合第一版：适合做极简专用硬件**

### 典型结构
`1090MHz 天线 -> LNA/SAW 前端 -> 包络检测/限带 -> ADC -> MCU`

### 适合原因
- 不需要 I/Q 全链路，不需要 FPGA
- 模拟侧先把信号“压缩成更容易处理的一维脉冲信号”
- MCU 只需要处理较低速的一路采样或比较器输出

### 优点
- 器件数明显少于 I/Q + FPGA 方案
- 软件开发简单很多
- 特别适合做“能收包、能解码、能输出”的教学型或演示型原型

### 缺点
- 鲁棒性不如 I/Q 方案
- 动态范围、复杂环境下抗干扰能力较弱
- 后续扩展空间有限

### 第一版是否推荐
**如果目标是极简系统，可以推荐。**

---

### 方案 P3：集成零中频接收芯片 + MCU/MPU
**推荐度：最高**  
**器件数量：较少**  
**开发难度：中**  
**是否适合第一版：最推荐的自研硬件平台路线**

### 典型结构
`1090MHz 天线 -> SAW/LNA -> 集成零中频接收芯片 -> I/Q -> MCU/MPU`

### 适合原因
- 比纯包络方案更稳
- 比“分立 LNA + Mixer + ADC + FPGA”简单很多
- 射频和基带之间的接口清晰，便于逐步产品化

### 优点
- 平衡了开发难度与性能
- 后续有机会演进成正式产品
- 不一定非要 FPGA 才能起步

### 缺点
- 仍然需要处理 I/Q 数据流
- 主控性能要求高于包络方案
- 模拟和时钟设计仍然需要一定经验

### 第一版是否推荐
**如果 RTL-SDR + PC 已经验证可行，这一条应作为第一优先自研路线。**

---

### 不建议作为第一版的方案：分立超外差 + ADC + FPGA
虽然性能潜力高，但从“器件最少、最容易开发”的角度看，它恰恰是最不合适的第一版方案，因为它会一下子把下面这些问题全引入：

- 1090MHz 射频匹配
- LNA 稳定性
- 混频与本振
- IF 滤波
- ADC 时钟
- FPGA 数据通路
- PCB 射频布局与屏蔽

这条路线适合第二版、第三版，不适合第一版。

---

## 一个非常明确的建议

如果你现在的目标不是“继续复用 RTL-SDR + PC”，而是：

- 在已有接收验证基础上做成**自己的 ADS-B 接收硬件**
- 用尽量少的器件把系统跑通
- 降低 1090MHz 模拟射频开发风险
- 后续还能演进成专用板卡或产品

那么建议直接选下面这个判断：

> **第一版自研平台优先选“1090MHz SAW/LNA + 集成接收芯片 + MCU/MPU”，而不是“成熟 SDR 模块 + PC”，更不要一上来就做“分立射频 + ADC + FPGA”。**

---

# 六、推荐的系统级架构

## 方案 1：射频前端 + ADC + FPGA + MCU
这是最经典、最稳妥的方案。

### 分工
#### 射频前端
- 天线匹配
- LNA
- SAW/BPF
- 下变频或零中频
- 模拟增益控制

#### ADC
- 采样 IF 或 I/Q
- 采样率一般几 MHz 到十几 MHz 即可

#### FPGA
- 前导码检测
- 能量检测
- 过采样定时
- PPM 判决
- CRC
- FIFO 缓冲

#### MCU
- 报文解析
- 串口/网口输出
- 参数管理
- 状态统计

### 为什么推荐 FPGA
ADS-B 码率不高，但对时序和连续流处理很友好，FPGA 非常适合：

- 滑窗检测
- 并行匹配
- 多相位候选判决
- 低延迟缓存

---

## 方案 2：射频前端 + ADC + 高性能 MCU/MPU
**推荐度：中**

适合条件：

- 采样率不高
- 前端已做一定限带/包络处理
- 目标是原型验证，不追求极致性能

### 适合器件
- STM32H7
- i.MX RT
- Zynq ARM 侧
- 其他带高速 DMA 的 MCU/MPU

### 风险
- 连续数据搬运压力大
- 高实时场景容易丢包
- 扩展性比 FPGA 差

### 建议
近距离演示、教学验证可以考虑。  
真要做稳定平台，还是建议 FPGA 参与。

---

# 六、射频前端怎么做最关键

1090MHz ADS-B 的第一大难点就是射频前端。

## 1. 天线
可选方案：

- **1090MHz 四分之一波长天线**
- **1090MHz 共线天线**
- **1090MHz 玻璃钢地面站天线**
- **小型贴片天线（近距离演示）**

### 设计要点
- 中心频率尽量贴近 1090MHz
- 驻波合理
- 馈线损耗低
- 室外部署优先高架、无遮挡

如果想收远距离飞机，天线高度和馈线质量非常重要。

---

## 2. LNA
通常建议加一级低噪声放大器。

### 目标
- 降低系统噪声系数
- 提高弱信号接收能力

### 关键参数
- NF：越低越好
- Gain：通常 10dB ~ 20dB
- IP3：不能太低，否则强信号下会压缩

### 注意
不要一味追求大增益。复杂环境里更稳的做法往往是：

- **LNA + SAW + 二级放大**
而不是
- **单级超高增益**

---

## 3. SAW / 带通滤波器
这个几乎是必需的。

### 为什么必须加
你只想收 1090MHz，但现实环境中还有很多强信号：

- 蜂窝基站
- 宽带杂散
- 其他航空频段
- 邻近发射机

如果没有足够带通滤波，后级 ADC 和解码门限会被污染。

### 建议
至少做到：

- 天线后或 LNA 后放一个 **1090MHz SAW/BPF**
- 环境复杂时做成：
  - 粗滤波
  - LNA
  - SAW 精滤波
  - 二级放大

---

## 4. 混频与本振
如果采用低 IF 架构，需要混频器和 LO。

### 关键点
- 本振相位噪声不能太差
- 频率精度要足够
- 镜像抑制要考虑
- PCB 上 LO 泄漏要控制

ADS-B 不是高阶调制，但本振太差也会影响脉冲边沿和检测稳定性。

---

# 七、采样率应该怎么选

很多人第一反应是“是不是要超高采样率”，其实不一定。

## 1. 基本事实
ADS-B 的速率是：

- **1 Mbps**
- bit 周期 **1 us**
- 脉冲宽度约 **0.5 us**

所以核心不是超宽带频谱覆盖，而是**时间分辨率足够高**。

## 2. 工程建议
### 原型可行范围
- **4 MHz ~ 8 MHz** 可做基础验证

### 更稳妥范围
- **8 MHz ~ 20 MHz** 更适合工程实现

### 例子
如果 10MHz 采样：

- 采样间隔 100ns
- 0.5us 脉冲有约 5 个采样点
- 1us bit 周期有约 10 个采样点

这已经足够做前导码检测和 bit 判决。

## 3. 不一定要直接采 1090MHz RF
完全可以：

- 先下变到低 IF
- 或零中频得到 I/Q
- 再用中等采样率 ADC

这比直接高速 RF 采样更现实。

---

# 八、数字基带解码链路怎么做

这是整个系统真正的核心。

## 1. 输入数据形式
可能有三种：

### 形式 A：实数 IF 采样
需要数字下变频或包络提取。

### 形式 B：I/Q 采样
最灵活，可计算幅度或功率：

`mag = I^2 + Q^2`

### 形式 C：模拟包络后的一维采样
实现简单，但鲁棒性通常不如 I/Q。

---

## 2. 预处理
常见步骤：

- 去 DC
- 限带
- 幅度归一化
- 噪声底估计
- 自适应门限生成

目标是得到适合脉冲检测的能量序列。

---

## 3. 前导码检测
ADS-B 报文前 8us 前导码固定，可使用：

- 滑动窗口匹配
- 峰值位置匹配
- 多点能量比值检测

### 常见思路
1. 找到疑似起始峰
2. 检查后续固定位置是否也出现能量峰
3. 检查不该有脉冲的位置是否足够低
4. 满足模板条件后判定为报文起点

### 为什么这一步很关键
如果前导码误检太多，会导致：

- 假包很多
- CRC 运算负担增加
- MCU/FIFO 压力上升

---

## 4. 位判决
找到前导码后，进入数据区判决。

每个 bit 为 1us，可分成前后两个半 bit：

- 前半窗能量大：判一种 bit
- 后半窗能量大：判另一种 bit

### 常见方法
积分比较：

- `E1 = 前半窗口能量和`
- `E2 = 后半窗口能量和`

若：

- `E1 > E2`，判一种 bit
- `E2 > E1`，判另一种 bit

0/1 映射可按实现统一。

### 关键问题
必须考虑：

- 采样时钟与真实 bit 边界不完全对齐
- 脉冲展宽
- 多径反射
- 噪声波动

### 工程对策
- 过采样
- 多相位候选比较
- 在前导码阶段估计最佳采样相位

---

## 5. 报文长度识别
解码后需要判断：

- 56 bit
- 112 bit

常见依据：

- DF 字段
- 长度和 CRC 结构

---

## 6. CRC 校验
这是必须实现的功能。

### 作用
- 过滤误码包
- 提高输出可信度
- 降低上层无效处理开销

### 建议
CRC 尽量放在 FPGA 或基带处理层完成。

---

# 九、ADS-B 报文解析要解析什么

如果只是“收原始包”，做到 bit + CRC 就够了。  
如果要做成有用的平台，至少建议解析以下字段：

## 1. ICAO 地址
飞机唯一地址，最基础字段。

## 2. 呼号
即航班号等标识信息。

## 3. 高度
通常是编码后的气压高度信息。

## 4. 位置
涉及 CPR（Compact Position Reporting）算法。

### 注意
位置通常不能靠单包完全恢复，往往需要：

- even / odd 帧配合
- 时间配对
- 全局/局部解码逻辑

## 5. 速度与航向
包括：

- 地速
- 航向
- 垂直速度

## 6. 状态字段
例如：

- 发射机能力
- 监视状态
- 紧急状态

---

# 十、如果你要自己做完整平台，最难的是哪几件事

## 1. 射频动态范围
现实中会同时出现强近场信号和弱远场信号，导致：

- 前端压缩
- ADC 饱和
- 门限漂移
- 弱包漏检

### 对策
- 合理增益分配
- 滤波先行
- 高线性 LNA / VGA
- 必要时双增益路径

---

## 2. 前导码误检
噪声尖峰或其他脉冲信号也可能长得像前导码。

### 对策
- 更严格的模板检测
- 峰值间隔一致性检查
- 数据区统计验证
- CRC 最终过滤

---

## 3. 时序偏差
采样点不一定刚好落在最佳判决位置。

### 对策
- 稍提高采样率
- 多相位积分比较
- 在前导码阶段估计最佳时序

---

## 4. 多径与脉冲变形
建筑反射、天线环境、模拟带宽不足，都会让脉冲畸变。

### 对策
- 射频和模拟带宽不要过窄
- 不要只依赖单点采样
- 尽量采用积分/能量判决

---

## 5. CPR 位置解码
这通常不是硬件最难，而是协议处理和工程边界最难。

### 对策
第一版先做到：

- 稳定输出原始包
- 稳定解析 ICAO / 高度 / 呼号 / 速度

第二版再加强：

- CPR 全局位置解码
- 航迹管理
- 地图显示

---

# 十二、硬件选型建议（按“器件最少、开发最容易”优先）

下面不给出单一唯一型号，而是给出**选型优先级 + 器件类别建议 + 适合的组合方式**。  
核心原则不是“指标最强”，而是：

- **可买到**
- **资料多**
- **评估板/模块多**
- **外围器件少**
- **调试门槛低**

## 1. 最推荐的第一版硬件组合

### 组合 A：成熟 SDR 模块 + 上位机/嵌入式主控（已验证基线方案）
**适合人群：** 想最快看到结果，或需要接收性能对照基线  
**推荐度：中**

#### 建议组合
- **天线**：1090MHz 专用 ADS-B 天线
- **前端**：外置 1090MHz LNA + SAW（如环境复杂时加入）
- **接收端**：成熟 SDR 模块
- **主控**：
  - PC（最快验证）
  - 树莓派 / Linux 小主机
  - 或性能够用的嵌入式 SoC

#### 为什么它适合作为基线
- 模块生态成熟
- 驱动和样例多
- 先解决“有没有包、算法通不通”
- 几乎不需要第一版自己啃 RF 原理图和高速 ADC

#### 选型建议
优先找满足下面特征的模块：
- 覆盖 1090MHz
- 社区资料多
- 有稳定驱动
- 能连续输出 IQ 或已有人做过 ADS-B 接收验证
- 市场上容易买到配套 LNA/SAW 模块

---

### 组合 B：1090MHz SAW/LNA 前端 + 集成接收芯片 + MCU/MPU
**适合人群：** 想做自己的板，但不想第一版就做复杂射频链路  
**推荐度：最高**

#### 建议组合
- **天线**
- **1090MHz SAW**
- **低噪声放大器 LNA**
- **集成式接收芯片**（内部完成大部分频率变换/基带输出）
- **MCU/MPU**

#### 这套组合为什么最推荐
- 比 USB SDR 模块更像“自己的硬件平台”
- 比分立混频器 + ADC + FPGA 简单得多
- 器件数仍可控制在较低水平

#### 主控建议
- **极简原型**：STM32H7、i.MX RT 这类高性能 MCU
- **更容易做系统集成**：树莓派 CM、Linux SoC、小型 ARM 板

#### 什么时候选它
- 你希望板子是自己设计的
- 但又不想第一版就碰 FPGA 和复杂 IF 架构

---

### 组合 C：前端包络化 + MCU
**适合人群：** 追求最低开发门槛、教学演示、近距离验证  
**推荐度：中高**

#### 建议组合
- 天线
- LNA
- SAW/BPF
- 包络检测/检波
- ADC 或高速比较器
- MCU

#### 优点
- 器件少
- 算法实现简单
- 不需要处理 I/Q

#### 缺点
- 容易受模拟链路细节影响
- 抗干扰和适应性不如 I/Q
- 只适合做基础版和演示版

---

## 2. 各器件模块怎么选

## 2.1 天线
优先选择：

- **1090MHz 专用 ADS-B 天线**
- 有明确驻波和增益参数
- 如果是室外长期部署，优先玻璃钢地面站天线
- 如果是桌面近距离演示，可先用磁吸天线或小型 1090MHz 天线

### 建议
从“最容易开发”的角度，**不要第一版自己做天线**。  
直接买成熟 1090MHz 天线，能少掉很多不确定性。

---

## 2.2 LNA
选择原则：

- 工作中心覆盖 1090MHz
- NF 低
- 增益不要过高，通常 10~20dB 更稳妥
- 线性度不能太差
- 尽量选有现成模块/评估板的器件

### 建议
第一版优先选**成品 LNA 模块**，不要自己裸设计 LNA。  
因为 LNA 稳定性、匹配和自激问题很容易拖慢开发。

---

## 2.3 SAW / BPF
选择原则：

- 中心频率贴近 1090MHz
- 插损不要过大
- 带外抑制足够
- 优先选 ADS-B/1090MHz 场景已有应用记录的器件或模块

### 建议
如果环境较复杂，**SAW 基本上是必加项**。  
从开发效率看，带屏蔽的小模块通常比自己画滤波网络省事很多。

---

## 2.4 接收芯片 / 接收模块
这是第一版最关键的选型点。

### 优先级建议
1. **集成接收芯片评估板/模块**
2. **自己画接收芯片最小系统板**
3. **成熟 SDR 模块（作为对照基线）**
4. **最后才是分立 Mixer + ADC + FPGA**

### 为什么这样排
因为用户真正想要的是 ADS-B 平台，而不是先把 RF 教材从头做一遍。

### 选择时重点看
- 1090MHz 接收是否已有成熟案例
- 是否有稳定驱动和参考设计
- 输出是 IQ、低 IF 还是包络
- 与主控连接是否方便
- 供电是否简单
- 是否有评估板

---

## 2.5 ADC
如果采用包络或低 IF 方案：

- **4~20MSPS** 一般就够做工程验证
- **8~12bit** 更稳妥
- 优先选接口简单、资料多的器件

### 建议
如果接收芯片内部已集成 ADC，**第一版优先用集成 ADC**。  
不要为了“可控”而把器件数翻倍。

---

## 2.6 主控器件
从“最容易开发”角度，排序如下：

### 第一梯队
- **树莓派 / Linux 小主机 / ARM SoC**
- 原因：软件开发快、调试方便、日志和网络功能现成

### 第二梯队
- **STM32H7 / i.MX RT 等高性能 MCU**
- 原因：适合做小型独立设备，成本和功耗更可控

### 第三梯队
- **FPGA**
- 原因：实时性强，但会显著提高开发门槛

### 结论
如果你的目标是“第一版尽快做成”，**优先 Linux SoC 或高性能 MCU，不要先上 FPGA。**

---

## 3. 推荐的实际选型策略

### 策略 1：最推荐的自研平台策略
- 1090MHz 成熟天线
- SAW + LNA 模块
- 集成接收芯片评估板或小模块
- STM32H7 / i.MX RT / Linux SoC

**适合目标：** 第一版就开始形成自己的专用平台

---

### 策略 2：最快成功策略（基线/对照）
- 1090MHz 成熟天线
- 外置 ADS-B 常用 LNA + SAW 模块
- 成熟 SDR 模块
- PC/树莓派

**适合目标：** 最短时间内收包和解码，作为算法与接收效果基线

---

### 策略 3：极简演示策略
- 1090MHz 天线
- LNA + SAW
- 包络检波
- MCU

**适合目标：** 做教学实验、演示样机、近距离验证

---

## 4. 一句话选型结论

如果你的决策标准是：

- **器件最少**
- **最容易开发**
- **最快看到结果**

那么对“自己做硬件平台”这个目标来说，首选不是 FPGA 专用接收机路线，也不是继续停留在 RTL-SDR + PC，而是：

> **1090MHz 专用天线 + 成熟 LNA/SAW 模块 + 集成接收芯片 + MCU/SoC**

进一步说：

- **想做自己的第一版硬件：LNA/SAW + 集成接收芯片 + MCU**
- **想保留一条最省事的对照链路：SDR 模块 + PC/树莓派**
- **想追求后续性能上限：第二版再上 ADC + FPGA**

# 十三、推荐的器件思路

下面不是唯一答案，而是选型思路。

## 1. 前端器件
### LNA
关注：

- 1090MHz 工作点
- 低 NF
- 足够线性度

### 滤波器
关注：

- 中心频率
- 插损
- 带宽
- 带外抑制

### 混频器 / 直接变频芯片
关注：

- 是否易于在 1090MHz 实现
- 输出 IF / I/Q 形式
- 本振方案
- 集成度

---

## 2. ADC
### 采样率建议
- 几 MHz 到十几 MHz
- I/Q 方案则需要双路同步采样

### 分辨率建议
- **8 bit** 可做基础版
- **10~12 bit** 更稳妥

### 重点
不要只看位数，更要看：

- ENOB
- 输入带宽
- 时钟抖动
- 接口方式

---

## 3. 数字处理器件
### FPGA
适合：

- Lattice
- Xilinx
- Intel/Altera

资源不必特别大，但需要足够做：

- 流处理
- 缓冲
- CRC
- 接口桥接

### MCU
适合：

- STM32H7
- NXP i.MX RT
- 其他带高速 DMA 的器件

### SoC
如果要做联网、Web、图形显示，SoC 更方便，例如：

- Zynq
- ARM Linux + FPGA

# 十二、最务实的开发顺序

## 第 1 阶段：先验证解码算法
目标：

- 先证明你能正确解码 ADS-B

建议：

- 先用公开 IQ 数据或现成采样数据
- 在 PC 上用 Python / C 跑通：
  - 前导码检测
  - PPM 判决
  - CRC
  - 基础字段解析

### 阶段结果
至少做到：

- 能输出合法原始包
- 能显示 ICAO / 高度 / 呼号等信息

---

## 第 2 阶段：做数字板原型
目标：

- 把解码链路迁移到 FPGA/MCU

建议：

- 先不接最复杂射频前端
- 先喂测试数据
- 先验证实时性和缓存结构

### 重点
- 数据流不断
- 前导码误检率可接受
- CRC 正确
- 输出稳定

---

## 第 3 阶段：接入射频前端
目标：

- 真正从天线收包

建议：

- 先用较稳妥的 1090MHz 前端模块或评估板
- 先做近距离实验
- 再做远距离测试

### 主要看什么
- 灵敏度
- 假包率
- 饱和问题
- 供电噪声
- PCB 射频布局

---

## 第 4 阶段：做专用化硬件
目标：

- 从“能用”做到“像产品”

包括：

- 更好的天线接口
- 电源完整性
- 屏蔽与接地
- 时钟与温漂控制
- 接口与外壳
- 室外部署能力

---

# 十三、PCB 与硬件实现注意事项

## 1. 射频走线
1090MHz 虽不算极高频，但绝不能随便画。

### 要点
- 50 欧阻抗控制
- 走线尽量短
- 过孔尽量少
- 射频层参考地连续
- LNA 输入输出隔离

---

## 2. 电源
很多接收问题最后都能追到电源噪声。

### 建议
- 射频模拟、ADC、数字电源分区
- LDO 噪声要关注
- PLL / LO 电源要干净
- 避免数字开关噪声污染前端

---

## 3. 时钟
ADC 和 LO 的时钟质量非常重要。

### 重点
- 相位噪声
- 抖动
- 温漂
- 布线隔离

---

## 4. 屏蔽
板上若同时有 MCU、FPGA、网口、开关电源，内部干扰会很明显。

### 建议
- 射频前端加屏蔽罩
- 模拟/数字分区明确
- 高速数字边沿远离 LNA 输入

---

# 十四、输出接口怎么设计

常见输出接口：

- UART
- USB
- Ethernet
- Wi-Fi

## 推荐优先级
### 1. UART
最简单，适合调试。

### 2. USB
适合直连 PC。

### 3. Ethernet
最推荐产品化版本使用，因为：

### 4. Wi-Fi
适合便携演示，但不建议作为第一优先主链路。

# 十六、如果只想做“最小可用系统”，应该怎么砍需求

## 硬件最小集
- 1090MHz 天线
- LNA
- 1090MHz SAW
- 简化接收前端
- ADC
- FPGA 或高性能 MCU
- UART/USB 输出

## 功能最小集
- 连续收包
- 前导码检测
- 112bit 包解码
- CRC 校验
- 原始包输出
- 基础字段解析（ICAO、DF、部分高度/呼号）

## 先不要做
- 复杂 AGC
- 极致灵敏度优化
- 完整 CPR 地图系统
- 多天线分集
- 多站同步定位
- 全套 Web 平台

因为这些会严重拖慢第一版。

# 十八、最推荐的实现路线

## 目标 A：尽快做出来
建议路线：

1. PC 上先跑通 ADS-B 解码算法
2. 如果 RTL-SDR + PC 已验证可行，就把它保留为基线参考
3. 第一版自研硬件直接转向“SAW/LNA + 集成接收芯片 + MCU/SoC”
4. 先稳定输出原始报文，再决定是否进一步压缩 BOM 或改为 MCU 独立运行
5. 最后再逐步增强字段解析与显示

### 这一目标下的明确建议
如果只按“器件最少、最容易开发”来定**自研平台**：

> **优先选“集成接收芯片 + 主控”，把 RTL-SDR + PC 作为参考对照，不要第一版就做 FPGA 射频专用板。**

---

## 目标 B：做成真正自己的硬件平台
建议路线：

1. 先做数字链路和协议解析
2. 第一版用集成射频前端
3. 第二版改成自研 LNA + SAW + 变频链路
4. 第三版优化 PCB、电源、时钟、屏蔽
5. 最终再做联网和产品化封装

# 十九、一个最务实的结论

如果只用一句话总结：

> **如果 RTL-SDR + PC 已经实现，那么下一步最现实的第一版自研方案，不是继续围绕 SDR 模块做文章，也不是直接上分立超外差，而是采用“1090MHz 天线 + LNA/SAW 模块 + 集成接收芯片 + MCU/SoC”的平台，把重点放在前导码检测、PPM 解码和报文解析上。**

如果后续再追求更高性能、远距离和产品化能力，再升级为：

> **1090MHz 射频前端 + 中等采样率 ADC + FPGA/MCU 的专用解码链路。**

再直白一点：

- **第一难点是射频前端**
- **第二难点是稳定的脉冲检测与同步**
- **第三难点是工程化而不是协议本身**

最建议的顺序：

1. **先验证解码算法**
2. **再做数字处理板**
3. **再接入 1090MHz 前端**
4. **最后优化成完整专用接收平台**
